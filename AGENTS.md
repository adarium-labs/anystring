## OVERVIEW
Ada library `anystrings` — a generic string-abstraction crate. One signature package (`Anystrings`) is instantiated against four interchangeable backends (Unbounded_String, Wide, Wide_Wide, UXStrings). Backend is picked **at build time** by swapping source directories via the `STRING_TYPE` GPR external. SPARK_Mode is enabled on the signature package; backends are not (yet) all SPARK-clean.

## STRUCTURE
```

├── anystrings.gpr           # library project; selects backend via STRING_TYPE
├── alire.toml               # crate metadata (no runtime deps for default build)
├── src/

├── config/                  # generated by Alire — DO NOT edit by hand
```

## CODE MAP
| Symbol | Type | Location | Role |
|--------|------|----------|------|
| `Anystrings` | generic package | `src/anystrings.ads` | Signature: 30+ formal subprograms; defines public API via expression functions |
| `String_Types` | package (4 copies) | `src/strings/<variant>/string_types.ads` | User-facing facade; only **one** is in the build at a time |
| `*_Strings` (e.g. `Standard_Strings`) | package instance | `src/strings/<variant>/<variant>_strings.ads` | `package X is new Anystrings (...)` |
| `*_Operations` | package | `src/strings/<variant>/*_operations.ads/adb` | Concrete impls fed to the generic |

The library’s entry point for consumers is **`String_Types`**, not `Anystrings`. Consumers `with String_Types;` and never instantiate the generic themselves.

## CONVENTIONS
- Ada 2012 (`-gnat2012`); max line length 120 (`-gnatyM120`, also enforced by `package Format`).
- File charset: UTF-8.
- Doc comments use the `--  @summary` / `--  @description` leading style (see `package Documentation` in the GPR).
- Binder uses `-Es` for symbolic tracebacks.
- Latin-1 is the canonical interchange encoding at the API edge: every backend implements `To_String_Type (String) -> String_Type` and `To_Latin_1 (String_Type) -> String`. UTF-8 / Unicode-code-point semantics are **backend-specific** (UXString = code points, Standard = bytes).
- `String_Types` always exposes `"&"`, `"="`, `"<"`, `Length`, `Element`, `Index`, `Slice`, `Trim`, `To_Lower/Upper`, `Starts_With`, `Ends_With`, `Hash`, `Contains`, `Is_Equals_Sign`, `Is_Dash`. Every new backend must rename-export this exact surface.

## ANTI-PATTERNS (THIS PROJECT)
- **Do not** `with Anystrings;` from user code — go through `String_Types`.
- **Do not** add Unbounded_String-specific behaviour to `String_Types` of another backend; the four `string_types.ads` files must present an **identical** Ada interface (only the underlying types differ).
- **Do not** edit anything in `config/` or `lib/` — both are generated.
- **Do not** assume `Length` counts characters: in the `standard` backend it counts **bytes**.
- **Do not** break `SPARK_Mode` on `src/anystrings.ads` when adding new operations; keep them as expression functions with explicit `Pre`/`Post` where indices are involved.
- **Do not** introduce new formals to the generic without updating **all four** `*_strings.ads` instantiations and **all four** `string_types.ads` re-exports in the same change.

## UNIQUE STYLES
- Backend selection by **source directory swap**, not by tagged-type dispatch. The four `string_types.ads` files share the same package name; whichever directory is in `Source_Dirs` wins.
- The signature package exposes both the formal subprograms (e.g. `Length`) and "wrapper" expression functions (e.g. `Get_Length`, `Is_Null_Or_Empty`, `Find_Index`) — the wrappers exist so SPARK contracts can be written on top of them.

## COMMANDS
```bash
# Default build (Unbounded_String backend)
alr build

# Pick a backend
STRING_TYPE=wide_string alr build
STRING_TYPE=wide_wide_string alr build
STRING_TYPE=uxstring alr build              # adds uxstrings dependency
STRING_TYPE=custom STRING_PATH=/abs/path alr build

# Library kind (default static)
ANYSTRING_LIBRARY_TYPE=relocatable alr build

# Run the demo
cd examples && alr run
```

## NOTES
- `examples/` is **its own Alire crate** with a path-pin to `..`; it is not built by the parent `alr build`.
- `uxstring` backend depends on the external `uxstrings` crate; `alire.toml` at the root does **not** declare that dependency because the default build is `standard`. Adding uxstrings as a hard dep would force every consumer to pull it in.
- `share/anystring/` is currently empty but is registered as an install artifact in the GPR (`package Install`) — anything dropped there ships with `alr install`.
- The `gnatprove` skill is available for SPARK proof work on `src/anystrings.ads`; backends are not all SPARK-clean today.
